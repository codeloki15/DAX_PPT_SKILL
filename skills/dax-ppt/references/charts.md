# Charts

How to create a chart spec with `dax.py chart`, what the engine validates, and how that spec becomes a native, editable PowerPoint chart on export.

## 1. The CLI

```
dax.py --workspace DIR chart --id ID --type TYPE [flags]
```

| Flag | Required | Meaning |
|---|---|---|
| `--id` | yes | `chart_id`. Also the spec filename and the `data-chart-id` in the embed. |
| `--type` | yes | One of the 9 types below. argparse rejects anything else before the engine runs. |
| `--categories` | effectively | Comma-separated labels. Split on `,`, each `.strip()`ed. Omitting it sends `[]` → `"categories must be a non-empty list of labels"`. |
| `--series` | one of | Repeatable. `'Name:v1,v2,v3'`. |
| `--series-json` | one of | JSON array, or `@file.json`. **Overrides** `--series` entirely when both are given. |
| `--title` | no | Chart title. Rendered in the preview and as a native PPTX chart title (11pt bold, `12263F`). |
| `--colors` | no | Comma-separated 6-digit hex. Semantic encoding only — see §7. |
| `--number-format` | no | Excel format code, e.g. `'#,##0'`. |
| `--totals` | no | Waterfall only. Comma-separated category indices. |

Output: one JSON object on stdout. Exit non-zero if the payload has an `error` key.

```json
{
  "status": "created",
  "chart_id": "rev-trend",
  "embed_html": "<div class=\"chart-embed\" data-chart-id=\"rev-trend\" style=\"flex:1;min-height:200px;\"></div>",
  "usage": "Paste embed_html into the slide inside a container that has real height, ..."
}
```

### `--series` (simple)

```bash
python3 scripts/dax.py --workspace ./decks/q3 chart \
  --id rev-by-segment \
  --type column \
  --categories "Enterprise,Mid-Market,SMB,Partner" \
  --series 'FY24:12.4,8.1,5.6,2.3' \
  --series 'FY25:15.9,9.4,5.1,3.8' \
  --title "Revenue by segment ($M)" \
  --number-format '$#,##0.0'
```

Parsing rule: the string must contain `:`. Name is everything before the first `:` (stripped); values are the comma-split remainder, each `float()`ed, empty items skipped.

| Bad input | Error |
|---|---|
| `--series 'Revenue 12,18'` | `--series must look like 'Name:1,2,3' (got 'Revenue 12,18')` |
| `--series 'Revenue:12,abc'` | `--series values must all be numbers (got '12,abc')` |

### `--series-json` (complex)

Use when a name contains a `:` or a comma, or when the data is generated by `dax.py aggregate`.

```bash
python3 scripts/dax.py --workspace ./decks/q3 chart \
  --id arr-mix --type column_stacked \
  --categories "Q1,Q2,Q3,Q4" \
  --series-json '[{"name":"New: logos","values":[3.1,3.9,4.4,5.2]},{"name":"Expansion","values":[1.2,1.6,2.1,2.4]}]'
```

Or from a file:

```bash
python3 scripts/dax.py --workspace ./decks/q3 chart \
  --id arr-mix --type column_stacked \
  --categories "Q1,Q2,Q3,Q4" \
  --series-json @/tmp/arr_series.json
```

A malformed value gives `--series-json is not valid JSON: <parser message>`.

## 2. The 9 chart types

| `--type` | Use it when | Native PPTX type |
|---|---|---|
| `column` | Comparing a handful of categories; the default bar chart. Vertical. | `COLUMN_CLUSTERED` |
| `bar` | Same, but labels are long or there are many categories. Horizontal. | `BAR_CLUSTERED` |
| `line` | A metric over time, 2+ periods, continuous. | `LINE` |
| `area` | A cumulative total over time where the filled mass is the point. | `AREA` |
| `pie` | Share of one whole, ≤5 slices. Single series. | `PIE` |
| `doughnut` | Same as pie, with room for a centre figure. Single series. | `DOUGHNUT` |
| `column_stacked` | Composition per period, vertical. | `COLUMN_STACKED` |
| `bar_stacked` | Composition per category, horizontal. | `BAR_STACKED` |
| `waterfall` | Bridging an opening figure to a closing figure through deltas. Single series. | `COLUMN_STACKED` + hidden base series |

**Single-series types.** `SINGLE_SERIES_TYPES = {"pie", "doughnut", "waterfall"}`. Passing any count other than exactly one:

```
chart_type 'pie' requires exactly one series
```

Data labels are added automatically only for `column` / `bar` with exactly one series (9pt, `221F20`). The legend is shown only for multi-series non-waterfall charts and for `pie` / `doughnut`.

## 3. Validation rules and exact errors

Checked in this order; the first failure returns and nothing is written to disk.

| Rule | Exact error |
|---|---|
| `chart_id` must match `^[a-zA-Z0-9_\-]{1,40}$` | `chart_id must be 1-40 chars of letters, digits, '_' or '-'` |
| `chart_type` in `CHART_TYPES` | `Unknown chart_type 'x'. Valid: ['area', 'bar', 'bar_stacked', 'column', 'column_stacked', 'doughnut', 'line', 'pie', 'waterfall']` |
| categories non-empty list | `categories must be a non-empty list of labels` |
| series non-empty list | `series must be a non-empty list of {name, values} objects` |
| single-series types get exactly 1 | `chart_type 'waterfall' requires exactly one series` |
| each item is a dict with `values` | `series[1] must be an object with 'name' and 'values'` |
| `len(values) == len(categories)` | `series[0] has 3 values but there are 4 categories - they must match` |
| values are numeric | `series[0] values must all be numbers` |
| colors are 6-digit hex | `colors must be 6-digit hex values like '00A0DC'` |
| `totals` only on waterfall | `totals only applies to waterfall charts` |
| `totals` are integers | `totals must be a list of category indices (integers)` |
| `totals` in range | `totals indices must be within 0..4` |

Notes:
- Colors are normalised before the check: leading `#` stripped, uppercased. `#00a0dc` and `00A0DC` both pass and are stored as `00A0DC`.
- `totals` are deduped and sorted: `--totals 4,0,0` is stored as `[0, 4]`.
- A missing `name` in `--series-json` defaults to `Series 1`, `Series 2`, … (1-based).
- Categories are coerced with `str()`; values with `float()`.

## 4. Waterfall convention

Values are **deltas**, not absolute levels. `--totals` marks the indices that are full bars from zero.

Per category, walking a `running` accumulator:

| Case | Base | Height | Color |
|---|---|---|---|
| index in `totals`, value non-zero | 0 | value (and `running` is **reset** to it) | `12263F` (total) |
| index in `totals`, value `0` | 0 | the current `running` — computed for you | `12263F` (total) |
| value ≥ 0 | `running` | value | `00A0DC` (up) |
| value < 0 | `running + value` | `-value` | `B3341F` (down) |

So: **the opening bar carries its real value; the closing bar carries `0` and the engine computes it.** Writing the closing figure explicitly would reset the running total and hide any arithmetic error in the deltas.

Worked example — $3.0M opening ARR bridging to a computed close:

```bash
python3 scripts/dax.py --workspace ./decks/q3 chart \
  --id arr-bridge \
  --type waterfall \
  --categories "FY24 ARR,Enterprise,SMB,Churn,FY25 ARR" \
  --series 'ARR:3000,800,400,-300,0' \
  --totals "0,4" \
  --title "FY24 to FY25 ARR bridge ($K)" \
  --number-format '#,##0'
```

Resulting bars:

| Category | Value passed | Base | Height | Color |
|---|---|---|---|---|
| FY24 ARR | 3000 | 0 | 3000 | total |
| Enterprise | 800 | 3000 | 800 | up |
| SMB | 400 | 3800 | 400 | up |
| Churn | -300 | 3900 | 300 | down |
| FY25 ARR | 0 | 0 | 3900 | total |

On export this is a `COLUMN_STACKED` chart with two series: `_base` (fill and line set to background, i.e. invisible) and the real series, whose points are colored individually. `gap_width = 60`. No legend.

## 5. The stored spec

Written to `<workspace>/charts/<chart_id>.json` (`CHARTS_DIR/<id>.json`), `json.dump(..., indent=2)`. All 8 keys are always present; nulls are written explicitly.

```json
{
  "chart_id": "arr-bridge",
  "type": "waterfall",
  "title": "FY24 to FY25 ARR bridge ($K)",
  "categories": ["FY24 ARR", "Enterprise", "SMB", "Churn", "FY25 ARR"],
  "series": [{ "name": "ARR", "values": [3000.0, 800.0, 400.0, -300.0, 0.0] }],
  "colors": null,
  "number_format": "#,##0",
  "totals": [0, 4]
}
```

| Field | Type | Note |
|---|---|---|
| `chart_id` | str | The CLI flag is `--id`. |
| `type` | str | The CLI flag is `--type`; the Python arg is `chart_type`. |
| `title` | str \| null | |
| `categories` | [str] | |
| `series` | [{name, values}] | `values` are always floats. |
| `colors` | [str] \| null | Normalised uppercase hex, no `#`. |
| `number_format` | str \| null | |
| `totals` | [int] | `[]` for every non-waterfall chart. |

`dax.py preview` loads **every** `*.json` in `charts/` and injects them into the preview page, keyed by the spec's own `chart_id` field — not the filename. A hand-copied file whose filename and `chart_id` disagree silently shadows another chart.

## 6. The embed contract

`embed_html` is returned verbatim and must be pasted into the slide HTML:

```html
<div class="chart-embed" data-chart-id="arr-bridge" style="flex:1;min-height:200px;"></div>
```

It has **no intrinsic height**. Drop it into a container that gives it real height or the chart collapses to nothing in the preview and exports at the 1in × 0.5in floor:

```html
<div class="exh" style="flex:1;display:flex;flex-direction:column;">
  <div class="exh-t">EXHIBIT 1 | FY24 to FY25 ARR bridge</div>
  <div class="chart-embed" data-chart-id="arr-bridge" style="flex:1;min-height:200px;"></div>
</div>
```

Keep `flex:1;min-height:200px` on the embed and make sure every ancestor up to `.slide-content` is a flex column with a resolved height. Do not replace the `style` attribute.

## 7. Colors

`BRAND_SERIES_COLORS`, applied by series index in exactly this order, cycling with `i % 6`:

| # | Hex | |
|---|---|---|
| 0 | `00A0DC` | brand blue |
| 1 | `12263F` | navy |
| 2 | `6A7C90` | slate |
| 3 | `8FD3EE` | light blue |
| 4 | `3C4456` | charcoal |
| 5 | `D4D9E0` | light grey |

Waterfall bars ignore the ramp: up `00A0DC`, down `B3341F`, total `12263F`. Axis text `6A7C90`, gridlines `E4E8ED`.

**Rule: omit `--colors`.** The default ramp is the brand. Pass `--colors` only when a color *means* something — a highlighted "us" bar against grey competitors, red for a decline, a fixed color per named product carried across several exhibits. Never to make a chart look nicer.

```bash
# Legitimate: Data Axle highlighted, competitors neutral (pie colors are per-slice)
python3 scripts/dax.py --workspace ./decks/q3 chart \
  --id share --type pie \
  --categories "Data Axle,Competitor A,Competitor B,Other" \
  --series 'Share:38,27,21,14' \
  --colors "00A0DC,D4D9E0,D4D9E0,D4D9E0"
```

`colors[i]` is used when `i` is in range; beyond that the ramp resumes. For `pie` / `doughnut` the index is the **slice**, not the series.

## 8. `number_format`

An Excel format code string, stored as-is and applied to the value-axis tick labels (`number_format_is_linked = False`) and to data labels on single-series `column` / `bar`.

| Data | `--number-format` |
|---|---|
| Whole currency | `'$#,##0'` |
| Currency, 1 decimal | `'$#,##0.0'` |
| Millions with suffix | `'$#,##0.0,,"M"'` |
| Percent from a 0–1 fraction | `'0.0%'` |
| Percent already 0–100 | `'0.0"%"'` |
| Plain thousands | `'#,##0'` |

Not applied to `pie` / `doughnut` axes (they have none).

## 9. Spec → native PowerPoint chart

`dax.py export` does not generate the chart; it post-processes an exported deck.

1. Playwright opens `slides/live_preview.html` headless.
2. It measures every `.chart-embed[data-chart-id]` inside every `.slide-content`, recording `{dom_index, chart_id, x, y, w, h}` with x/y/w/h as fractions 0..1 of the slide. It strips the enclosing `.exh` panel's border/background/shadow and **replaces the placeholder with a same-size spacer** — hiding it is not enough, the rasteriser would drop a blank picture over the native chart.
3. The browser exports the deck via dom-to-pptx; Playwright saves it.
4. `insert_native_charts` reopens it with python-pptx, converts the fractions back to EMU against the real slide size, and calls `slide.shapes.add_chart(...)` with a `CategoryChartData` built from the stored spec. Size floors: 1in wide, 0.5in tall.
5. Native tables and speaker notes are inserted the same way, then the file is saved in place.

The result is a real PowerPoint chart object — the recipient can click it, open "Edit Data" and change the numbers.

### What to check in the export JSON

```json
{
  "status": "success",
  "exported": true,
  "output_path": "/abs/path/final_outputs/Q3_Review_20260922_141203.pptx",
  "slides_exported": 12,
  "native_charts": { "inserted": ["arr-bridge", "rev-by-segment"], "errors": [] },
  "native_tables": { "inserted": 2, "errors": [] },
  "file_size_bytes": 884213
}
```

- `native_charts.inserted` is a **list of chart_ids**. Every chart you created and embedded must appear in it. A missing id means the placeholder was never rendered (wrong `data-chart-id`, or the slide was not in the preview).
- `native_charts.errors` is a list of strings:

| Error | Cause |
|---|---|
| `python-pptx not installed. Run: pip install python-pptx` | Export "succeeded" but every chart is a flat picture. Run `dax.py doctor`. |
| `arr-bridge: no stored spec found` | The embed references an id with no `charts/<id>.json`. |
| `arr-bridge: slide index 7 out of range (deck has 6)` | Preview and export are out of sync; rebuild with `dax.py preview`. |

- `native_charts` is **absent entirely** when no `.chart-embed` was found in the preview. If you embedded charts and the key is missing, the preview is stale — re-run `dax.py preview` before exporting.

## 10. Editing a chart later

**Re-run `dax.py chart` with the same `--id`.** The spec file is overwritten with no prompt and no merge — every flag you omit reverts to its default, so pass the full invocation again.

```bash
# Corrected SMB figure; --title and --number-format must be repeated or they are lost
python3 scripts/dax.py --workspace ./decks/q3 chart \
  --id arr-bridge --type waterfall \
  --categories "FY24 ARR,Enterprise,SMB,Churn,FY25 ARR" \
  --series 'ARR:3000,800,520,-300,0' \
  --totals "0,4" \
  --title "FY24 to FY25 ARR bridge ($K)" --number-format '#,##0'
```

The `embed_html` is unchanged, so the slide HTML needs no edit. Re-run `dax.py preview` to pick up the new spec.

The user can also edit chart data in the browser preview while `dax.py open` is serving: `POST /api/chart/<id>` merges `categories`, `series`, `title`, `colors`, `number_format` (and `totals` for waterfall) over the stored spec and re-validates through the same `create_chart`, so browser edits obey every rule in §3. Those edits write to the same `charts/<id>.json`. **The preview is shared state** — if the user has the browser open, read the spec back before overwriting it from the CLI.
